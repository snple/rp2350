# 双舵机控制器 — 上位机接口说明

本文面向**上位机软件开发者**：描述如何从 PC 侧连接设备、收发命令、处理应答与异常。
硬件接线、固件实现、PWM 参数等不在本文范围内。

| 项目 | 内容 |
|------|------|
| 协议版本 | 1.0（ASCII 行文本） |
| 设备类型 | USB CDC ACM 虚拟串口 |
| USB 标识 | VID `0x2E8A` / PID `0x000A`，产品名 `RP2350 Servo Controller` |
| 控制对象 | 2 个位置型舵机（下文称**通道 0**、**通道 1**） |

---

## 1. 通信模型

一问一答的**行文本协议**：上位机发一行命令，设备回一行应答。

```text
   上位机                                    设备
     │   "90.5 45.0\n"                        │
     │───────────────────────────────────────►│
     │   "OK 90.5 45.0\r\n"                   │
     │◄───────────────────────────────────────│
```

- 所有字节为 **ASCII**
- 请求以 `\n`、`\r` 或 `\r\n` 结束（三者均可）
- 应答固定以 `\r\n` 结束
- 请求与应答**无序号、无校验、无重传机制**：可靠性由上位机按"发一条、等一条"保证

## 2. 连接设备

### 2.1 端口识别

| 系统 | 设备名 |
|------|--------|
| Linux | `/dev/ttyACM0`（已有其它 CDC 设备时为 `ttyACM1`…） |
| macOS | `/dev/cu.usbmodem*` |
| Windows | 设备管理器中的 "USB 串行设备 (COMx)" |

Linux 下按产品名定位最稳定（端口号会变化）：

```bash
ls -l /dev/serial/by-id/
```

### 2.2 串口参数

| 参数 | 值 |
|------|-----|
| 波特率 | 任意（建议填 **115200**） |
| 数据位 / 校验 / 停止位 | 8 / None / 1 |
| 流控 | 无（RTS/CTS、XON/XOFF 均关闭） |

> USB CDC 是虚拟串口，**波特率数值不影响实际速率**，底层走 USB 批量传输。

### 2.3 DTR 必须置位（重要）

设备只在主机**打开端口且 DTR = 1** 时处理命令。DTR = 0 时收到的数据被丢弃，不会产生任何应答。

- pyserial：打开后设置 `ser.dtr = True`
- .NET (`System.IO.Ports`)：`port.DtrEnable = true`
- C/C++ termios：打开后调用 `ioctl(fd, TIOCMBIS, &TIOCM_DTR)`

`screen`、`minicom`、`cat`、`printf >` 等工具默认会置位，一般无需额外处理。

### 2.4 权限（Linux）

```bash
sudo usermod -aG dialout $USER    # 重新登录生效
# 或临时
sudo chmod a+rw /dev/ttyACM0
```

## 3. 协议定义

### 3.1 请求：设置两个通道的角度

```text
<角度0><分隔符><角度1><行结束>
```

| 字段 | 格式 | 说明 |
|------|------|------|
| 角度0 | 十进制，`0`~`180`，可带一位小数 | 通道 0（GPIO0）目标角度，单位度 |
| 分隔符 | 空格 / 制表符 / 逗号，可重复 | `"90,45"`、`"90   45"` 均合法 |
| 角度1 | 同角度0 | 通道 1（GPIO1）目标角度 |
| 行结束 | `\n` / `\r` / `\r\n` | |

两路角度必须**同时给出**，没有"只设置一路"的写法。

#### 角度写法对照

| 写法 | 结果 |
|------|------|
| `90` | ✅ 90.0° |
| `90.5` | ✅ 90.5° |
| `180` | ✅ 180.0° |
| `0.0` | ✅ 0.0° |
| `90.25` | ❌ `ERR`（小数超过一位） |
| `90.` | ❌ `ERR`（小数点后必须有一位数字） |
| `.5` | ❌ `ERR`（整数部分不能省略） |
| `180.1` | ❌ `ERR`（超出上限） |
| `-1` | ❌ `ERR`（不支持负数） |
| `abc` | ❌ `ERR`（非数字） |

#### 输入限制

| 项目 | 限制 | 违反后 |
|------|------|--------|
| 单行长度 | ≤ **32 字节**（不含行结束符） | 该行作废，返回 `ERR` |
| 角度个数 | 必须**恰好 2 个** | 返回 `ERR` |
| 空行（只有行结束符） | 忽略 | 不产生应答 |

### 3.2 应答

| 应答 | 格式 | 含义 |
|------|------|------|
| 成功 | `OK <角度0> <角度1>\r\n` | 已生效；回显实际应用的角度，**固定一位小数** |
| 失败 | `ERR\r\n` | 该行非法；**舵机保持原位置不动** |

```text
发送: "90 90\n"          → 应答: "OK 90.0 90.0\r\n"
发送: "45.5,135.0\n"     → 应答: "OK 45.5 135.0\r\n"
发送: "90.25 0\n"        → 应答: "ERR\r\n"
```

### 3.3 非应答输出

主机打开端口（DTR 0→1）时，设备会主动发两行提示信息，例如：

```text
RP2350 dual servo ready (IRQ)\r\n
send: <a0> <a1>, 0.0..180.0 (0.1 deg)\r\n
```

具体文字随固件版本变化。**上位机不应解析这两行**，只需遵守：

> 只有 `OK ` 开头的行、或内容为 `ERR` 的行才是命令应答；其他行一律忽略。

### 3.4 设备侧状态机行为

| 场景 | 设备行为 |
|------|----------|
| 上电 / 复位 | 两通道输出 **90.0°**，不产生主动输出 |
| 端口关闭（DTR 掉） | 丢弃未完成的行、清空待发应答；重新打开后从干净状态开始 |
| 行超长（第 33 个字节） | 立即 `ERR` 并清空该行，后续字节作为新行开始 |
| 连续多条命令 | 按到达顺序逐条执行，每条各自应答；最终位置由最后一条决定 |

## 4. 时序与可靠性

| 项目 | 数值 | 说明 |
|------|------|------|
| 舵机刷新周期 | 20 ms（50 Hz） | 舵机每 20 ms 采样一次脉宽 |
| 命令生效延迟 | 典型 < 1 ms | 收到完整行即写入 PWM |
| 建议命令间隔 | ≥ 20 ms | 更快不会更灵敏，但无副作用 |
| 到位时间 | 约 0.1~0.2 s / 60° | 取决于舵机型号与负载 |

> 命令只是"设定目标角度"，设备**不会**等待舵机到位。需要"到位后继续"时，
> 上位机自行等待（常见做法：每 60° 等 150~200 ms）。

### 4.1 应答缓冲与背压

设备待发应答缓冲为 **96 字节**。若上位机长期只写不读，缓冲填满后
**新的应答会被丢弃**（命令依然执行）。

因此：

- 必须**读取应答**，不要只写
- 推荐"发一条、等一条"的同步模型
- 若超时未收到应答，可**重发同一条命令**——设置角度是幂等的，重发无副作用

### 4.2 推荐调用流程

```text
发送命令（带行结束符）
   ↓
循环读取，直到读到一行：
   ├─ "OK  ..." → 成功，解析回显角度
   ├─ "ERR"     → 命令被拒（不要重试，先修正命令）
   └─ 其它行    → 忽略，继续读
   ↓
超时（建议 500 ms~1 s）→ 视为失败，可选择重发
```

---

## 5. 角度精度

- **协议精度 0.1°**：命令可按 0.1° 递增，`OK` 回显保留一位小数
- **物理精度取决于舵机**：模拟舵机典型 0.5~1°（死区 5~10 µs），数字舵机约 0.1°
- 因此不要把 0.1° 当成实际可控精度，闭环定位需外部反馈（编码器/IMU）

## 6. 示例代码

### 6.1 Python（pyserial）

依赖：`pip install pyserial`

```python
import time
import serial


class ServoController:
    """双舵机控制器上位机封装：error / timeout 均抛异常。"""

    def __init__(self, port, timeout=0.5):
        self.ser = serial.Serial(port, 115200, timeout=timeout)
        self.ser.dtr = True          # 必须置位，否则设备不处理命令

    def set_angles(self, angle0: float, angle1: float):
        """设置两个通道角度（度）。返回设备回显的 (a0, a1)。"""
        cmd = f"{angle0:.1f} {angle1:.1f}\n".encode("ascii")
        self.ser.write(cmd)

        deadline = time.monotonic() + 1.0
        while time.monotonic() < deadline:
            line = self.ser.readline().decode("ascii", "replace").strip()
            if not line:
                continue                      # 超时返回的空行
            if line == "ERR":
                raise ValueError(f"设备拒绝命令: {cmd!r}")
            if line.startswith("OK "):
                parts = line.split()
                return float(parts[1]), float(parts[2])
            # 其它行（如开机提示）忽略
        raise TimeoutError(f"未收到应答: {cmd!r}")

    def close(self):
        self.ser.close()


if __name__ == "__main__":
    ctl = ServoController("/dev/ttyACM0")

    print(ctl.set_angles(90, 90))              # (90.0, 90.0)

    # 互补扫描：通道0 0°→180°，通道1 反向
    for deg in range(0, 181):
        ctl.set_angles(deg, 180 - deg)
        time.sleep(0.02)                        # 与舵机刷新周期一致

    ctl.close()
```

### 6.2 命令行（Linux / macOS）

```bash
PORT=/dev/ttyACM0

# 交互式，可直接看到应答
screen "$PORT" 115200          # 退出：Ctrl-A 然后 K

# 脚本发送 + 打印应答
cat "$PORT" & CAT_PID=$!
sleep 0.2
printf '45.5,135.0\n' > "$PORT"
sleep 0.5
kill $CAT_PID
# 输出：OK 45.5 135.0
```

### 6.3 通信自检（无需舵机）

只插 USB、不接舵机也可验证链路：发送 `10.0 170.0`，收到 `OK 10.0 170.0` 即正常。

## 7. 常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 找不到串口设备 | 换 USB 数据线（部分线仅充电）；确认设备已上电；Linux 看 `dmesg \| tail` 是否有 `cdc_acm` |
| 能写但完全收不到数据 | ① DTR 未置位；② 没有读取端口；③ 端口被其它程序占用（Linux 用 `fuser -v /dev/ttyACM0`） |
| 一直返回 `ERR` | 行未以 `\n`/`\r` 结束（未刷新）；只有 1 个或 3 个角度；用了 `90.25`、`90.`、负数等非法写法 |
| 应答错乱、缺行 | 上位机读取不及时，96 字节缓冲被填满后应答被丢弃；改为同步收发 |
| 发了很多命令但设备无反应 | 命令未以行结束符结尾（部分库需要显式写 `\n`） |
| 拔插 USB 后异常 | 重新打开端口即可，设备会在 DTR 掉时清空协议状态 |
| Linux Permission denied | 加入 `dialout` 组或临时改权限 |
| 角度偏差 1~2° | 舵机机械误差/供电不足，非协议问题；协议回显与实际写入的脉宽是一致的 |

## 8. 版本与兼容性

- 本文对应**协议版本 1.0**
- 后续扩展保持向后兼容：
  - 现有请求格式与 `OK` / `ERR` 应答格式不变
  - 新增能力使用新的行前缀；旧上位机收到不认识的行应忽略
- 稳妥实现方式（两条即可）：
  1. 只把以 `OK ` 开头、或等于 `ERR` 的行当作应答
  2. 忽略其它所有输出行
